# Приложение Shoply

## Запуск

Нужен Python 3.10+. Сторонние серверные зависимости не требуются.

Из этой папки: `python3 backend/server.py`. Из корня репозитория: `python3 website/backend/server.py`.

На macOS можно открыть scripts/start.command двойным кликом. Оставьте окно сервера открытым. Адрес магазина — http://127.0.0.1:8765/, админка — http://127.0.0.1:8765/admin.html.

При первом входе задайте собственный логин и пароль (минимум 10 символов). Администратор один, встроенных учётных данных нет.

public/index.html можно открыть двойным кликом для просмотра каталога. Заказы и админка работают только через HTTP-сервер.

## Что работает

- 22 демо-товара, поиск, открытые фильтры категорий и цены, сортировка.
- Отдельный экран/URL каждого товара с описанием, галереей и свободными свойствами.
- Корзина и количество; корзина сохраняется в браузере.
- ФИО, телефон, почта/самовывоз; адрес скрыт и не требуется при самовывозе.
- Кнопка «Оплатить» сохраняет заказ в SQLite, показывает номер и «Ожидает оплаты». Онлайн-оплата не подключена, доставка не рассчитывается.
- Админка: оформление, товары, заказы. Название/логотип/основные цвета/Telegram; создание, редактирование и удаление товаров, категории, фото, произвольные свойства; контакты и состав заказов, смена статуса.

PNG/JPEG/WebP до 6 МБ, до 12 фото на товар. Категории автоматически попадают в фильтры. Флажок «Демонстрационный товар» управляет демо-маркировкой.

## Разделение кода

backend/server.py — точка запуска; класс Handler находится отдельно в backend/handler.py. HTTP-проверки и маршрутизация отделены от сервисов авторизации, товаров, заказов, оформления и загрузки изображений. database.py управляет транзакциями и гарантирует закрытие SQLite-соединений, validation.py проверяет входные данные. Схема SQLite и адреса API сохранены. public содержит только публичные страницы и ресурсы. CSS — public/assets/css, JavaScript — public/assets/js, изображения — public/assets/images, шрифты — public/assets/fonts. Сервер не раздаёт исходники backend, базу, тесты или материалы Codex.

## Данные и резервное копирование

SQLite: var/data/shoply.sqlite3. Фотографии владельца: public/assets/uploads. Обе директории исключены из Git. В свежем клоне создаётся чистый магазин без заказов и администратора.

Для резервной копии остановите сервер и скопируйте обе директории. Переносите базу и фотографии вместе. Локальная копия базы до реорганизации сохранена рядом как shoply-before-restructure.sqlite3; она также не входит в Git.

Переменные окружения: SHOPLY_PORT (по умолчанию 8765), SHOPLY_DATA_DIR (каталог SQLite). Сервер слушает только 127.0.0.1. Публикация, HTTPS и реальная оплата — отдельный этап.

## Проверки

Из папки website:

```sh
python3 tests/test_shop.py
node tests/test_frontend.cjs
node tests/test_admin.cjs
```

Первый тест запускает реальный API с временной SQLite; второй проверяет витрину, третий — вход и заказы админки. JavaScript-тесты исполняют файлы в порядке подключения из HTML с моделью DOM. Это не визуальные браузерные тесты.

Условия лицензирования Inter — public/assets/fonts/Inter-LICENSE.txt. Фотографии демо-товаров синтетические; происхождение и промпты находятся отдельно в ../codex/materials.


## Архитектура после рефакторинга

Сервер разделён по ответственности:

- `server.py` — запуск на 127.0.0.1.
- `handler.py` — единственный класс HTTP-обработчика, проверка запросов, маршруты и раздача public.
- `config.py` — пути, исходные настройки и состояние локальных сессий.
- `database.py` — схема, первоначальное заполнение, транзакции и чтение конфигурации.
- `auth_service.py` — вход, создание администратора, scrypt и ограничение попыток.
- `product_service.py` — каталог, создание, обновление и скрытие товаров.
- `order_service.py` — контакты, доставка, серверные цены, повтор заказа, история и статусы.
- `settings_service.py`, `upload_service.py` — оформление и загрузка изображений.
- `validation.py` — проверка текста, локальных путей, цен и свойств товара.
- `response.py` — результат сервиса: HTTP-статус, JSON-данные, необязательный cookie.

Изменения сервисов выполняются в одной транзакции запроса. HTTP-ответ отправляется после успешного commit; при исключении SQLite делает rollback, соединение закрывается в finally. Сервисы не читают HTTP-заголовки и не пишут в сокет.

Во фронтенде `shared.js` содержит общие операции DOM, форматирование и HTML-экранирование. `store-state.js` и `admin-state.js` содержат состояние соответствующей страницы. Файлы `store-cart`, `store-catalog`, `store-product`, `store-checkout`, `store-navigation` разделяют корзину, каталог, товар, оформление и переходы. `admin-auth`, `admin-settings`, `admin-products`, `admin-orders` разделяют области админки. `store.js` и `admin.js` подключают события и запускают страницы.

Порядок скриптов задан в HTML: общие функции → состояние → области приложения → запуск. Используются обычные скрипты без сборщика, чтобы сохранить просмотр витрины через file://. Новые функции объявляйте в файле своей области, документируйте назначение JSDoc-комментарием; Python-функции, методы и классы — docstring. Каждый новый класс размещайте в отдельном файле. Взаимодействие страниц идёт через API, а не через общее состояние.

Демонстрационный `products.js` одновременно читается браузером и загрузчиком начальных данных: правая часть присваивания должна оставаться валидным JSON. Не преобразовывайте её форматтером в JavaScript-объекты с некавыченными ключами или завершающими запятыми.

## Использованные рекомендации

- [PEP 8](https://peps.python.org/pep-0008/) — читаемое форматирование, явные импорты и небольшие функции.
- [PEP 257](https://peps.python.org/pep-0257/) — документирование модулей, классов и функций.
- [MDN: организация JavaScript по модулям](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules) — разделение связанных ответственностей. ES-модули требуют HTTP-загрузки; здесь сохранены обычные скрипты для file://.
- [OWASP: Input Validation](https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html) — серверная проверка входных данных и разрешающие списки путей, цветов и статусов.

Параметризованный SQL, HTML-экранирование, HttpOnly/SameSite cookie, проверка Origin/Host и расчёт заказа по серверным ценам сохранены. Это локальное приложение; публикация и подключение оплаты остаются отдельными задачами.
