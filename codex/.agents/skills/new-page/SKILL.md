# Сборка страницы

Прочитайте AGENTS.md, BRIEF.md, REFERENCES.md, DESIGN.md, materials/ASSETS.md, SITEMAP.md и HANDOFF.md. Для существующего сайта сначала изучите его компоненты и фактический вид. Запрос на доработку сохраняет одобренный дизайн; явная смена направления обновляет DESIGN.md.

## До кода

- Если бриф пуст, выполните brief. Не заставляйте владельца ещё раз утверждать известные решения.
- Определите главный смысл первого экрана, ведущий визуал и последовательность остальной страницы. Для каждой секции — зачем она нужна, чем отличается её композиция и что должен понять посетитель.
- Опирайтесь на просмотренные референсы. Проверьте конкретный перенос: типографика, масштаб, поля, положение предмета и характер движения. Одна похожая кнопка не воспроизводит эстетику.
- Прочитайте references/composition.md. Для изображений — references/images.md; для анимации — references/motion.md. recommendations в design-direction.md вторичны к брифу и принятым решениям.
- Временные токены shared/tokens.css замените выбранными. Не начинайте новую страницу с неизменённой стандартной палитры и системного display-шрифта.

## Собрать целиком

HTML/CSS/JavaScript без сборщика — базовый путь для первой страницы. Создайте index.html, локальные изображения/шрифты, осмысленные alt и title/description. Текст и необходимые ссылки доступны без JavaScript. Общие header/footer скрипты можно использовать, но необходимые навигация и контакты должны иметь HTML-fallback либо находиться в HTML сразу.

Секции могут быть полноширинными, текст — в общем контейнере. Повторяющиеся компоненты и токены переиспользуются. У форм без получателя нет отправки и ложного «успеха». Структура определяется проектом, а не фиксированными семью блоками.

Сгенерируйте настоящий файл изображения встроенным инструментом, если он нужен и доступен. Сохраните исходник и web-версию. Не завершайте задачу одним промптом вместо изображения. Внешний платный API автоматически не подключайте.

Сначала доведите страницу целиком, затем проводите один общий просмотр. Не тратьте бесконечные проходы на один hero, пока остальные блоки не собраны. Вторая страница использует те же токены и общие компоненты; обновите SITEMAP.md и меню.

## Передать результат

Прочитайте ../page-reviewer/SKILL.md и references/acceptance.md. Попросите отдельного проверяющего, если он доступен; он возвращает замечания, а не повторно запускает самого себя. Один список → один пакет исправлений → проверка изменённого. После существенной переделки обновите контракт и сделайте новый полноценный проход.

Обновите REVIEW.md и HANDOFF.md. Покажите живую страницу и кратко сообщите, что сделано, что реально проверено и какой остаток есть. Не обещайте публикацию, работающую форму или медицинскую/финансовую достоверность демонстрации, если этого нет.
