# Инструкции для Shoply

## Контекст проекта

- Прочитайте `README.md`. Приложение находится непосредственно в корне: `frontend/`, `backend/`, `public/`, `scripts/`, `tests/`, локальные данные — `var/`.
- Витрина и админка требуют HTTP. Исходники — в `frontend/`; `public/index.html`, `public/admin.html` и `public/assets/build/` генерируются сборкой.
- Сохраняйте компактный каталог, открытую панель фильтров и настройку оформления из админки.
- Онлайн-оплата не подключена. Оформление сохраняет заказ со статусом «Ожидает оплаты»; стоимость доставки уточняется отдельно. Не показывайте успешную оплату без интеграции.

## Архитектура и стиль

- Стек: Vue 3 + TypeScript + Vite, существующий CSS, Python 3.10+ стандартной библиотеки, SQLite. Node.js 22.12+ (рекомендуется 24 LTS) нужен для сборки и тестов; сторонних серверных пакетов нет.
- `backend/server.py` запускает сервер; `handler.py` отвечает за HTTP; сервисы — за предметную логику; `database.py` — за транзакции; `validation.py` — за проверку входных данных. Сервисы не пишут в сокет.
- Раздавайте только `public/`. Локальный сервер слушает `127.0.0.1`. В контейнере `SHOPLY_HOST=0.0.0.0` допустим только с явно заданным HTTPS-адресом `SHOPLY_PUBLIC_ORIGIN`; настройки Dokploy описаны в `docs/dokploy.md`.
- Во фронтенде используйте модули: общие типы, API и тема — `frontend/src/shared/`, витрина — `store/`, админка — `admin/`. Сохраняйте две точки входа и существующие hash-адреса. Не редактируйте собранные HTML вручную.
- `public/assets/js/products.js` используется загрузчиком SQLite: правая часть присваивания должна оставаться валидным JSON.
- Следуйте `.editorconfig`: 2 пробела, для Python — 4.
- Документируйте неочевидную логику и важные контракты: входные данные, результат, ограничения и побочные эффекты. Для Python используйте docstring, для JavaScript — JSDoc. Комментарии должны объяснять смысл или причину решения, а не повторять очевидный код.
- Разделяйте файлы по ответственности. Выносите класс в отдельный файл, когда у него самостоятельная ответственность или это упрощает поддержку.
- Сохраняйте параметризованный SQL, серверный расчёт цен, HTML-экранирование, проверки Origin/Host и защиту сессий. Изменения схемы должны сохранять существующие товары и заказы.
- При изменении интерфейса учитывайте обе темы, мобильные размеры, клавиатуру, видимый фокус и `prefers-reduced-motion`.

## Запуск и проверки

Все команды ниже выполняются из корня репозитория.

```sh
npm ci
npm run build
python3 backend/server.py
```

Магазин: `http://127.0.0.1:8765/`, админка: `/admin.html`. На macOS доступен `scripts/start.command`. Порт задаётся через `SHOPLY_PORT`, каталог SQLite — через `SHOPLY_DATA_DIR`.

Если порт занят, сначала определите процесс и проверьте ответ сайта. Работающий сервер Shoply используйте повторно; при необходимости перезапустите его в рамках согласованной задачи. Посторонний процесс не останавливайте.

```sh
npm run build
python3 tests/test_shop.py
node tests/test_frontend.cjs
node tests/test_admin.cjs
node tests/test_theme.cjs
python3 tests/test_deployment.py
git diff --check
```

- Полный набор проверок включает все пять тестов выше. GitHub Actions дополнительно собирает контейнер и проверяет пересоздание с сохранением данных. Для изменений запуска, защиты публичного адреса и Docker выполняйте `tests/test_deployment.py`; с Docker также `SHOPLY_TEST_IMAGE=shoply-test python3 tests/test_deployment.py` после сборки образа.
- Выбирайте проверки по затронутому поведению:
  - Серверная логика, API или хранение данных — `python3 tests/test_shop.py`; при изменении контракта API дополнительно проверяйте использующие его витрину и/или админку.
  - Логика витрины и оформления — `node tests/test_frontend.cjs`.
  - Логика админки — `node tests/test_admin.cjs`.
  - Общая тема — `node tests/test_theme.cjs` и тесты обеих страниц.
  - Общие скрипты — тесты всех использующих их страниц и функций.
  - CSS или визуальное поведение — проверка затронутых экранов в браузере на широком и мобильном размерах, в обеих темах; при изменении логики дополнительно запускайте соответствующие тесты.
- Для изменённых `.js`, `.mjs` и `.cjs` дополнительно выполняйте `node --check <путь>`.
- Проверки API используют временную SQLite. Для ручных экспериментов с записью задавайте отдельный `SHOPLY_DATA_DIR`; не используйте реальные заказы и учётную запись как тестовые данные.
- Тесты интерфейса — `frontend/tests/` (Vitest, Vue Test Utils, jsdom); старые команды `.cjs` запускают соответствующие наборы. Выполняйте `npm run typecheck`. Тесты не заменяют браузерную проверку.
- Публикуйте сборку только через `npm run build`: не очищайте `public/`, загрузки или демо-данные.
- Для правок только документации достаточно проверить пути, команды и `git diff --check`; тесты приложения запускать не нужно.

## Данные и документация

- Не добавляйте в Git секреты, личные абсолютные пути, SQLite из `var/data/` и пользовательские файлы из `public/assets/uploads/`.
- Не удаляйте и не перезаписывайте локальную базу, загрузки и архивы для подготовки чистого результата.
- Демонстрационные товары и синтетические изображения должны оставаться обозначенными как демонстрация.
- При существенном изменении поведения, архитектуры или запуска обновите `README.md` и при необходимости этот `AGENTS.md`.
