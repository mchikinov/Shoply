# Инструкции для Shoply

## Общение и работа

- Общайтесь с владельцем по-русски. Выполняйте задачу до проверенного результата; обычные обратимые правки не требуют повторного согласования.
- Перед изменениями смотрите `git status`. Сохраняйте чужие и незакоммиченные изменения, не откатывайте их ради своей задачи.
- Меняйте только необходимое для запроса. Не добавляйте зависимости, сборщик или новый фреймворк без причины в задаче.
- В итоговом ответе кратко укажите результат, выполненные проверки и конкретные непроверенные части.

## Контекст проекта

- Прочитайте `README.md`. Приложение находится непосредственно в корне: `backend/`, `public/`, `scripts/`, `tests/`, локальные данные — `var/`. Используйте актуальные пути без префикса `website/`.
- Витрину можно просматривать через `file://`, но заказы и админка требуют HTTP-сервера.
- Решения владельца важнее шаблонных дизайнерских приёмов. Сохраняйте компактный каталог, открытую панель фильтров и настройку оформления из админки.
- Онлайн-оплата не подключена. Оформление сохраняет заказ со статусом «Ожидает оплаты»; стоимость доставки уточняется отдельно. Не показывайте успешную оплату без интеграции.

## Архитектура и стиль

- Стек: HTML/CSS/обычные JavaScript-скрипты, Python 3.10+ стандартной библиотеки, SQLite. Сборщика нет.
- `backend/server.py` запускает сервер; `handler.py` отвечает за HTTP; сервисы — за предметную логику; `database.py` — за транзакции; `validation.py` — за проверку входных данных. Сервисы не пишут в сокет.
- Раздавайте только `public/`. Локальный сервер слушает `127.0.0.1`.
- В JavaScript сохраняйте порядок подключения в HTML: общие функции → состояние → области приложения → запуск. Общие операции держите в `shared.js`, логику — в соответствующем `store-*` или `admin-*` файле.
- `products.js` используется браузером и загрузчиком SQLite: правая часть присваивания должна оставаться валидным JSON.
- Следуйте `.editorconfig`: 2 пробела, для Python — 4. Новые Python-функции, методы и классы документируйте docstring, JavaScript-функции — JSDoc. Каждый новый класс размещайте в отдельном файле.
- Сохраняйте параметризованный SQL, серверный расчёт цен, HTML-экранирование, проверки Origin/Host и защиту сессий. Изменения схемы должны сохранять существующие товары и заказы.
- При изменении интерфейса учитывайте обе темы, мобильные размеры, клавиатуру, видимый фокус и `prefers-reduced-motion`.

## Запуск и проверки

Все команды ниже выполняются из корня репозитория.

```sh
python3 backend/server.py
```

Магазин: `http://127.0.0.1:8765/`, админка: `/admin.html`. На macOS доступен `scripts/start.command`. Порт задаётся через `SHOPLY_PORT`, каталог SQLite — через `SHOPLY_DATA_DIR`.

Если порт занят, сначала определите процесс и проверьте ответ сайта. Устаревший процесс этого проекта после переноса файлов перезапустите; посторонний процесс не останавливайте.

```sh
python3 tests/test_shop.py
node tests/test_frontend.cjs
node tests/test_admin.cjs
node tests/test_theme.cjs
git diff --check
```

- Полный набор проверок включает все четыре теста выше. GitHub Actions пока запускает только API, витрину, админку и проверку синтаксиса; тест темы запускайте отдельно.
- Запускайте проверки, относящиеся к изменению. При изменении общего API или скриптов обеих страниц проверяйте затронутые сценарии вместе.
- Для изменённых `.js` и `.cjs` дополнительно выполняйте `node --check <путь>`.
- Проверки API используют временную SQLite. Для ручных экспериментов с записью задавайте отдельный `SHOPLY_DATA_DIR`; не используйте реальные заказы и учётную запись как тестовые данные.
- JavaScript-тесты используют модель DOM и не заменяют браузерную проверку. Для визуальных изменений проверяйте затронутый экран в браузере на широком и мобильном размерах, если браузер доступен. Не выдавайте программные проверки за визуальные.
- Для правок только документации достаточно проверить пути, команды и `git diff --check`; тесты приложения запускать не нужно.
