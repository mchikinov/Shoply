# Серверная корзина — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Перенести корзину на сервер и требовать повторного подтверждения после изменений при оформлении.

**Architecture:** SQLite хранит снимок корзины, монотонную версию и идентификаторы выполненных операций. HttpOnly cookie связывает любой HTTP-клиент с гостевой корзиной; предметный сервис не зависит от транспорта. Чтение, изменения и оформление используют транзакцию с блокировкой записи до проверки каталога. Vue хранит последний серверный снимок и состояние запросов.

**Tech Stack:** FastAPI, Pydantic, SQLite, Vue 3, TypeScript, Pinia, Vitest.

**Spec:** [Эпик](../../epics/server-cart.md).

## Ограничения

- Работа в согласованной ветке `codex/server-cart`, в текущей рабочей папке.
- Существующие товары, заказы, оформление, темы и черновики сохраняются.
- По ответу пользователя старые локальные корзины не переносятся: проект не опубликован.
- Новых зависимостей, оплаты, складского учёта и мобильного приложения нет.
- Повторное согласование плана реализации не требуется: пользователь поручил начать согласованный эпик.

## Фокус проверки

- Потеря ответа добавления: повтор с тем же идентификатором не увеличивает количество снова.
- Изменение цены после чтения другим клиентом: старое подтверждение всё равно отклоняется.
- Повтор принятого заказа после добавления новых товаров не очищает новую корзину.
- Ошибка чтения корзины не выглядит как успешно загруженная пустая корзина.
- PATCH проходит существующие проверки Host/Origin; чужой идентификатор заказа не раскрывает подтверждение.

Интерфейс сервиса: `get_cart(db, cart_id)` возвращает снимок; `mutate_cart(db, cart_id, action, product_id, body)` возвращает результат API. Снимок содержит `lines`, `count`, `total`, `version`, `changes`. Позиция содержит данные товара, `quantity`, `subtotal`. Операции используют `request_id` и `version`; PATCH поддерживает точное `quantity` либо `delta`.

- Final: fixed гонка общего токена между вкладками — регрессионный тест «не теряет неподтверждённый заказ одной вкладки при повторе старого заказа в другой» RED→GREEN; все 30 тестов интерфейса прошли.
- Final: Ruling: токен неподтверждённого оформления изолирован в sessionStorage вкладки — устраняет перезапись другими вкладками и сохраняет reload; цена решения: после закрытия вкладки автоматическое восстановление потерянного подтверждения не гарантируется, принятый заказ остаётся в базе.
- Final: Ruling: миграция старых корзин, push-обновление экранов, складской учёт и оплата не добавлялись — следуем явным границам пользователя и эпика; последствия указаны в API-документации.
- Final: Ruling: автоматическая очистка старых гостевых корзин и нагрузочное масштабирование отложены до отдельной политики хранения — текущая задача для ещё не опубликованного магазина; цена решения: таблицы корзин и ключей операций растут до появления такой политики.
