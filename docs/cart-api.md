# API серверной корзины

## Идентификация

Сначала клиент вызывает `GET /api/cart` и сохраняет cookie `shoply_cart`.
Это случайный секрет с `HttpOnly`, `SameSite=Strict`, сроком один год
и `Secure` при публичном HTTPS-адресе. В SQLite хранится только SHA-256 секрета.
Без cookie создаётся новая независимая гостевая корзина. Она не связана
с административной сессией и сохраняется после перезапуска сервера.

API подходит веб-витрине и другим HTTP-клиентам, включая будущий мобильный:
нужно поддерживать cookie-хранилище и передавать cookie в следующих запросах.
Регистрация покупателя и синхронизация между устройствами не реализованы.

## Операции

| Действие | Запрос | JSON-поля |
| --- | --- | --- |
| Получить состав и итоги | `GET /api/cart` | Нет |
| Добавить количество | `POST /api/cart/items` | `id`, `quantity`, `version`, `request_id` |
| Изменить количество | `PATCH /api/cart/items/{id}` | `quantity` либо `delta`, `version`, `request_id` |
| Удалить позицию | `DELETE /api/cart/items/{id}` | `version`, `request_id` |
| Очистить корзину | `DELETE /api/cart/items` | `version`, `request_id` |

Изменяющие запросы передают JSON с `Content-Type: application/json`, включая
DELETE. Сохраняются проверки Host/Origin. Допустимо до 100 разных товаров
и до 999 единиц каждого; нулевое количество при PATCH удаляет позицию.
Сервер отклоняет превышение количества и недоступные товары.

Успешный ответ каждой операции — полный снимок: `lines`, `count`, `total`,
`version`, `changes`. В `lines` находятся актуальные данные товара, `quantity`
и серверная сумма позиции `subtotal`. Клиент отображает суммы без пересчёта.
Недоступные товары исключаются; `changes` описывает обнаруженные этим запросом
изменения с причинами `unavailable` и `price_changed`. Версия хранится в базе,
монотонно увеличивается при изменении снимка и не меняется от повторного чтения.
Ответы корзины и оформления имеют `Cache-Control: no-store`.

`request_id` — уникальный ключ операции (например, UUID). При потере ответа
повторите **тот же запрос с теми же полями и ключом**: операция не выполнится
дважды, ответ вернёт текущее состояние. Использование ключа с другим содержимым
даёт HTTP 409 с `code: request_conflict`. Устаревшая `version` даёт HTTP 409
с `code: cart_changed` и актуальной `cart`; действие не выполняется. После
просмотра изменений новое действие отправляется с новым ключом и новой версией.

## Оформление

`POST /api/orders` принимает `token`, `cart_version`, `fullname`, `phone`,
`delivery` и `address` для почтовой доставки. Состав, цены и итог берутся из
серверной корзины; переданные клиентом `items` и `total` не используются.
Старый запрос только с `items`, без `cart_version`, больше не создаёт заказ.

Если корзина изменилась, заказ не создаётся: HTTP 409 содержит
`code: cart_changed`, `error` и актуальную `cart`. Витрина показывает обновлённую
корзину, сохраняет контакты и ждёт повторного подтверждения пользователя.
Проверка и создание заказа выполняются в одной транзакции SQLite.

Успешный ответ содержит `id`, `status`, `total`, `delivery` и текущую `cart`.
Оформленные позиции очищаются атомарно с созданием заказа. Повтор с тем же
`token` и cookie возвращает прежнее подтверждение, не создаёт новый заказ
и не очищает товары, добавленные позже. Чужая корзина не может получить
подтверждение по этому токену. После потери ответа веб-витрина сохраняет токен
в `sessionStorage` своей вкладки и позволяет проверить оформление даже при
уже пустой серверной корзине. Перезагрузка той же вкладки сохраняет попытку;
другие вкладки не могут перезаписать или удалить её токен. После закрытия
вкладки автоматическое восстановление неподтверждённой попытки не гарантируется;
сам принятый заказ остаётся в базе и доступен администратору.

## Границы

В браузере хранится последний ответ в памяти и токен неподтверждённого заказа,
а состав в `localStorage` больше не сохраняется. По решению для ещё
не опубликованного проекта старые локальные корзины не импортируются.
Актуальность гарантируется на момент запроса; автоматического обновления
открытого экрана без запроса, учёта остатков и резервирования нет.

Интерактивная документация доступна на `/docs`, OpenAPI — на `/openapi.json`.
