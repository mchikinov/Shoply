# Shoply

Локальный интернет-магазин с каталогом, корзиной, оформлением заказа и админкой. Стек: HTML/CSS/JavaScript, Python 3.10+ стандартной библиотеки и SQLite. Сборщик и сторонние серверные пакеты не нужны; для проверок JavaScript нужен Node.js.

## Структура

Приложение находится непосредственно в корне репозитория.

```text
backend/                     HTTP-обработчик, сервисы API, SQLite и валидация
  server.py                  точка запуска
public/                      единственная публичная директория
  index.html                 витрина и оформление заказа
  admin.html                 админка
  assets/
    css/                     стили, темы и дизайн-токены
    js/                      логика витрины, админки и демо-данные
    images/                  изображения демо-товаров
    fonts/                   локальный Inter и лицензия
    uploads/                 пользовательские фото; исключены из Git
scripts/start.command        запуск на macOS
tests/                       проверки API, витрины, админки и темы
var/data/                    локальная SQLite; исключена из Git
AGENTS.md                    инструкции Codex для проекта
.github/workflows/checks.yml проверки GitHub Actions
```

## Запуск

Из корня репозитория:

```sh
python3 backend/server.py
```

На macOS можно открыть `scripts/start.command` двойным кликом. Оставьте процесс сервера работающим; для остановки нажмите Ctrl+C в его терминале.

- [Магазин](http://127.0.0.1:8765/)
- [Админка](http://127.0.0.1:8765/admin.html)

В новом клоне база и 22 демо-товара создаются автоматически. При первом открытии админки задайте логин и пароль (минимум 10 символов). Администратор один, встроенных учётных данных нет.

`public/index.html` можно открыть напрямую для просмотра каталога. Заказы и админка работают только через HTTP-сервер.

Сервер слушает `127.0.0.1`. Переменные окружения:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `SHOPLY_PORT` | Порт сервера | `8765` |
| `SHOPLY_DATA_DIR` | Каталог базы SQLite | `var/data` в корне проекта |

Если порт занят старым процессом Shoply после переноса файлов, остановите этот процесс и запустите сервер заново из текущей структуры.

## Что работает

- 22 демо-товара, поиск, открытые фильтры категорий и цены, сортировка.
- Отдельный экран/URL каждого товара с описанием, галереей и свободными свойствами.
- Корзина и количество; корзина сохраняется в браузере.
- ФИО, телефон, почта/самовывоз; адрес скрыт и не требуется при самовывозе.
- Кнопка «Оплатить» сохраняет заказ в SQLite, показывает номер и «Ожидает оплаты». Онлайн-оплата не подключена, доставка не рассчитывается.
- Админка: оформление, товары, заказы. Название/логотип/основные цвета/Telegram; создание, редактирование и удаление товаров, категории, фото, произвольные свойства; контакты и состав заказов, смена статуса.

PNG/JPEG/WebP до 6 МБ, до 12 фото на товар. Категории автоматически попадают в фильтры. Флажок «Демонстрационный товар» управляет демо-маркировкой.

## Данные и резервное копирование

База с товарами, настройками, администратором и заказами — `var/data/shoply.sqlite3`. Пользовательские фотографии — `public/assets/uploads/`. Эти данные исключены из Git; чистый клон не содержит личных данных и заказов.

Для резервной копии остановите сервер и скопируйте каталог данных и пользовательские фотографии. При заданном `SHOPLY_DATA_DIR` используйте выбранный каталог. Восстанавливайте базу и фото вместе.

## Проверки

Все команды выполняются из корня репозитория:

```sh
python3 tests/test_shop.py
node tests/test_frontend.cjs
node tests/test_admin.cjs
node tests/test_theme.cjs
```

- `test_shop.py` запускает API с временной SQLite и проверяет серверные сценарии и сохранение данных.
- `test_frontend.cjs` проверяет витрину, корзину, оформление, ошибки и повтор запроса.
- `test_admin.cjs` проверяет вход, создание администратора, товары, заказы и выход.
- `test_theme.cjs` проверяет системную тему, переключение, сохранение и синхронизацию.

JavaScript-тесты используют модель DOM и не заменяют визуальную проверку в браузере. Проверки API не используют рабочую базу.

Дополнительные проверки:

```sh
for file in public/assets/js/*.js tests/*.cjs; do
  node --check "$file" || exit 1
done
git diff --check
```

GitHub Actions при push и pull request запускает тесты API, витрины и админки, а также проверку синтаксиса JavaScript. Тест темы пока запускается отдельно приведённой выше командой.

## Архитектура

Сервер разделён по ответственности:

- `server.py` — запуск на 127.0.0.1.
- `handler.py` — единственный класс HTTP-обработчика, проверка запросов, маршруты и раздача public.
- `config.py` — пути, исходные настройки и состояние локальных сессий.
- `database.py` — схема, первоначальное заполнение, транзакции и чтение конфигурации.
- `auth_service.py` — вход, создание администратора, scrypt и ограничение попыток.
- `product_service.py` — каталог, создание, обновление и скрытие товаров.
- `order_service.py` — контакты, доставка, серверные цены, повтор заказа, история и статусы.
- `settings_service.py`, `upload_service.py` — оформление и загрузка изображений.
- `validation.py` — проверка текста, локальных путей, цен и свойств товара.
- `response.py` — результат сервиса: HTTP-статус, JSON-данные, необязательный cookie.

Изменения сервисов выполняются в одной транзакции запроса. HTTP-ответ отправляется после успешного commit; при исключении SQLite делает rollback, соединение закрывается в finally. Сервисы не читают HTTP-заголовки и не пишут в сокет.

Во фронтенде `shared.js` содержит общие операции DOM, форматирование и HTML-экранирование. `store-state.js` и `admin-state.js` содержат состояние соответствующей страницы. Файлы `store-cart`, `store-catalog`, `store-product`, `store-checkout`, `store-navigation` разделяют корзину, каталог, товар, оформление и переходы. `admin-auth`, `admin-settings`, `admin-products`, `admin-orders` разделяют области админки. `store.js` и `admin.js` подключают события и запускают страницы.

Порядок скриптов задан в HTML: общие функции → состояние → области приложения → запуск. Используются обычные скрипты без сборщика, чтобы сохранить просмотр витрины через file://. Новые функции объявляйте в файле своей области, документируйте назначение JSDoc-комментарием; Python-функции, методы и классы — docstring. Каждый новый класс размещайте в отдельном файле. Взаимодействие страниц идёт через API, а не через общее состояние.

Демонстрационный `products.js` одновременно читается браузером и загрузчиком начальных данных: правая часть присваивания должна оставаться валидным JSON. Не преобразовывайте её форматтером в JavaScript-объекты с некавыченными ключами или завершающими запятыми.

## Ограничения и материалы

Онлайн-оплата не подключена: заказ сохраняется со статусом «Ожидает оплаты», доставка уточняется отдельно. Хостинг и HTTPS — отдельный этап. GitHub Pages не запускает Python/SQLite; рабочему магазину нужен серверный хостинг.

Фотографии демо-товаров синтетические. Лицензия Inter — `public/assets/fonts/Inter-LICENSE.txt`.

Инструкции для работы с проектом: [AGENTS.md](AGENTS.md).
