# Shoply

Локальный интернет-магазин с каталогом, корзиной, оформлением заказа и админкой. Фронтенд: Vue 3, TypeScript, Vue Router, Pinia и Vite. Сервер: Python 3.10+, FastAPI, Pydantic, Uvicorn и SQLite. Для разработки, сборки и тестов интерфейса нужен Node.js 22.13+ (рекомендуется 24 LTS) с npm.

## Структура

Приложение находится непосредственно в корне репозитория.

```text
frontend/                    исходники Vue и тесты (структура описана ниже)
package.json                 команды разработки, сборки и тестирования
requirements.txt            версии FastAPI и Uvicorn
vite.config.ts               две HTML-точки входа и локальный прокси
backend/                     FastAPI-приложение, сервисы API, SQLite и валидация
  app.py                     маршруты API, HTTP-защита и публичные файлы
  schemas.py                 схемы запросов и документация OpenAPI
  server.py                  точка запуска
public/                      единственная публичная директория
  index.html                 собранная витрина (не редактировать вручную)
  admin.html                 собранная админка (не редактировать вручную)
  assets/
    build/                   сгенерированные модули Vue; исключены из Git
    fonts/                   локальный Inter и лицензия
    uploads/                 пользовательские фото; исключены из Git
scripts/start.command        запуск на macOS
tests/                       проверки API, витрины, админки, темы и деплоя
Dockerfile                   контейнер приложения для Dokploy
docs/dokploy.md              настройка публикации и постоянного хранения
var/data/                    локальная SQLite; исключена из Git
AGENTS.md                    инструкции Codex для проекта
.github/workflows/checks.yml проверки GitHub Actions
```

## Запуск

Из корня репозитория, при первом запуске:

```sh
npm ci
npm run build
python3 -m pip install -r requirements.txt
python3 backend/server.py
```

После изменения исходников снова выполните `npm run build`. Сборка сначала
проверяет типы, создаёт `.frontend-build/`, затем публикует только две HTML-страницы
и файлы `public/assets/build/`. SQLite и пользовательские загрузки не очищаются.
Старые файлы сборки сохраняются для открытых вкладок; эта папка не попадает в Git.

Для разработки с автоматическим обновлением интерфейса оставьте Python-сервер
работать в одном терминале, а в другом выполните:

```sh
npm run dev
```

Откройте `http://127.0.0.1:5173/` или `/admin.html`. Vite слушает только loopback,
направляет `/api` и `/assets` на Python, по умолчанию на порт `8765`. При другом
порте запускайте Vite с тем же `SHOPLY_PORT`. Используйте именно `127.0.0.1:5173`:
локальный прокси адаптирует только этот Origin; остальные источники не получают
обхода серверной проверки. Публичный режим с HTTPS проверяйте через собранный
сайт и Python, а не через dev-сервер.

На macOS можно открыть `scripts/start.command` двойным кликом: он проверяет Node.js,
создаёт локальное Python-окружение `.venv`, при необходимости устанавливает
зависимости и собирает интерфейс. Оставьте процесс сервера работающим; для
остановки нажмите Ctrl+C в его терминале.

- [Магазин](http://127.0.0.1:8765/)
- [Админка](http://127.0.0.1:8765/admin.html)

В новом клоне база создаётся автоматически с пустым каталогом. Товары добавляются через админку. При первом открытии админки задайте логин и пароль (минимум 10 символов). Администратор один, встроенных учётных данных нет.

Витрина и админка работают через HTTP. Просмотр через `file://` больше не поддерживается.

Сервер слушает `127.0.0.1`. Переменные окружения:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `SHOPLY_PORT` | Порт сервера | `8765` |
| `SHOPLY_DATA_DIR` | Каталог базы SQLite | `var/data` в корне проекта |
| `SHOPLY_HOST` | Интерфейс сервера; в контейнере `0.0.0.0` | `127.0.0.1` |
| `SHOPLY_PUBLIC_ORIGIN` | Основной адрес сайта со схемой, без пути; для внешнего запуска HTTPS | пусто, локальный режим |
| `SHOPLY_SETUP_TOKEN` | Секрет первой настройки, от 32 символов; обязателен для нового публичного магазина | пусто |

Python не загружает `.env` автоматически. `.env.example` служит образцом для настроек окружения.

Если порт занят старым процессом Shoply после переноса файлов, остановите этот процесс и запустите сервер заново из текущей структуры.

## Что работает

- Каталог товаров, поиск, открытые фильтры категорий и цены, сортировка.
- Отдельный экран/URL каждого товара с описанием, галереей и свободными свойствами.
- Корзина хранится в SQLite; сервер проверяет товары, цены и количества при каждом запросе.
- ФИО, телефон, почта/самовывоз; адрес скрыт и не требуется при самовывозе.
- Кнопка «Оплатить» сохраняет заказ в SQLite, показывает номер и «Ожидает оплаты». Онлайн-оплата не подключена, доставка не рассчитывается.
- Админка: оформление, товары, заказы, тестовые данные. Название/логотип/основные цвета/Telegram; создание, редактирование и удаление товаров, категории, фото, произвольные свойства; контакты и состав заказов, смена статуса.

PNG/JPEG/WebP до 6 МБ, до 12 фото на товар. Категории автоматически попадают в фильтры.

## Данные и резервное копирование

База с товарами, настройками, администратором, корзинами и заказами — `var/data/shoply.sqlite3`. Пользовательские фотографии — `public/assets/uploads/`. Эти данные исключены из Git; чистый клон не содержит личных данных и заказов.

Для резервной копии остановите сервер и скопируйте каталог данных и пользовательские фотографии. При заданном `SHOPLY_DATA_DIR` используйте выбранный каталог. Восстанавливайте базу и фото вместе.

## Проверки

Все команды выполняются из корня репозитория после `npm ci` и `npm run build`:

```sh
python3 tests/test_shop.py
node tests/test_frontend.cjs
node tests/test_admin.cjs
node tests/test_theme.cjs
python3 tests/test_deployment.py
```

- `test_shop.py` запускает API с временной SQLite и проверяет серверные сценарии и сохранение данных.
- `test_frontend.cjs` запускает сценарии Vue через Vitest и проверяет витрину, корзину, оформление, ошибки и повтор запроса.
- `test_admin.cjs` запускает сценарии Vue через Vitest и проверяет вход, создание администратора, товары, заказы и выход.
- `test_theme.cjs` запускает сценарии Vue через Vitest и проверяет системную тему, переключение, сохранение и синхронизацию.

Тесты Vue используют Vue Test Utils и jsdom; все сценарии запускаются командой `npm test`. Они не заменяют визуальную проверку в браузере. Проверки API не используют рабочую базу.

Дополнительные проверки:

```sh
npm run typecheck
npm run lint
npm run format:check
for file in public/assets/js/*.js tests/*.cjs scripts/*.mjs; do
  node --check "$file" || exit 1
done
git diff --check
```

GitHub Actions при push и pull request запускает тесты API, витрины, админки, темы, публичного режима и контейнера, а также проверку синтаксиса JavaScript. После успешных проверок push в `main` может запускать Dokploy; публикация выключена до настройки переменных и секрета. Подробности — [инструкция Dokploy](docs/dokploy.md).

Интерактивная документация API доступна на `/docs`, схема OpenAPI — на
`/openapi.json`. Контракт оформления использует серверную корзину; старый
запрос только с `items` больше не создаёт заказ. Гостевая cookie, операции,
версии и повторное подтверждение описаны в [API корзины](docs/cart-api.md).
API использует обычные HTTP-запросы и cookie и подходит будущему мобильному
клиенту с cookie-хранилищем.

## Архитектура

Сервер разделён по ответственности:

- `server.py` — запуск Uvicorn на 127.0.0.1 по умолчанию и проверка настроек публичного режима.
- `app.py` — FastAPI-маршруты, проверка запросов и раздача разрешённых файлов из `public/`.
- `schemas.py` — Pydantic-схемы запросов для проверки данных и OpenAPI.
- `config.py` — пути, исходные настройки и состояние локальных сессий.
- `database.py` — схема, первоначальное заполнение, транзакции и чтение конфигурации.
- `auth_service.py` — вход, создание администратора, scrypt и ограничение попыток.
- `product_service.py` — каталог, создание, обновление и скрытие товаров.
- `cart_service.py` — актуализация, суммы, версии и безопасные повторы операций корзины.
- `cart_routes.py` — HTTP API корзины, гостевая cookie и транзакции с блокировкой записи.
- `order_service.py` — контакты, доставка, серверные цены, повтор заказа, история и статусы.
- `settings_service.py`, `upload_service.py` — оформление и загрузка изображений.
- `validation.py` — проверка текста, локальных путей, цен и свойств товара.
- `response.py` — результат сервиса: HTTP-статус, JSON-данные, необязательный cookie.

Изменения сервисов выполняются в одной транзакции запроса. HTTP-ответ отправляется после успешного commit; при исключении SQLite делает rollback, соединение закрывается в finally. Сервисы не читают HTTP-заголовки и не пишут в сокет.

Фронтенд находится в `frontend/src/`. Витрина и админка — два приложения Vue
с собственными экземплярами Pinia и Vue Router. Общие модули переиспользуются,
состояние между HTML-страницами автоматически не разделяется. Серверная сессия
остаётся в HttpOnly cookie, цены заказа рассчитывает Python.

```text
frontend/
  index.html, admin.html      исходные HTML с ранней установкой темы
  src/
    main.ts, admin.ts        подключение Vue, Pinia, Router и стилей
    App.vue, AdminApp.vue    оболочки витрины и админки
    views/
      storefront/           каталог, товар, оформление, подтверждение
      admin/                вход, оформление магазина, товары, заказы
    components/
      storefront/           карточки, фильтры, корзина, форма заказа, шапка
      admin/                форма товара и редактор фотографий
      common/               переключатель темы
    router/                 маршруты и совместимость старых hash-ссылок
    stores/                 каталог, корзина, заказ, сессия, уведомления
    composables/            реактивная логика фильтров, форм, темы, фокуса
    services/               HTTP-клиент и предметные функции API
    types/                  контракты данных Python API
    utils/                  форматирование, файлы, ошибки, чтение корзины
    assets/styles/          исходные CSS, дизайн-токены и обе темы
  tests/                    компонентные и интеграционные проверки
```

### Где размещать код

- `views` связывают страницу с состоянием и собирают её из компонентов.
- `components` отвечают за части интерфейса. Карточка товара получает `product`
  через props и сообщает о действиях через emits. Локальные поля формы остаются
  в форме; отдельный глобальный store для каждого поля не нужен.
- `stores` содержат данные, необходимые нескольким компонентам. Корзина хранит
  последний серверный снимок и состояния запросов; количество, цены и суммы
  определяет бэкенд. Очередь запросов сохраняет порядок ответов. Checkout store
  хранит подтверждение заказа и токен
  `shoply-pending-token` в `sessionStorage` своей вкладки для безопасного повтора
  после ошибки сети, включая перезагрузку той же вкладки.
- `composables` — функции `use…`, выделяющие реактивную логику и побочные эффекты.
  Например, `useProductFilters` управляет фильтрами экземпляра каталога,
  `useProductEditor` — независимым черновиком товара, `useCartOverlay` — фоном
  корзины, анимацией, прокруткой и возвратом фокуса.
- `services` знают адреса API и форматы запросов. Они возвращают данные или
  выбрасывают ошибку, не импортируют stores и не показывают уведомления.
  Защищённые действия админки выполняются через `auth.run`: при HTTP 401
  локальная сессия закрывается, черновики панели уничтожаются.
- `utils` содержат обычные вспомогательные функции без состояния приложения.
  Общие контракты находятся в `types/api.ts`; типы одной формы остаются рядом с ней.

Пример для изучения: `router/storefront.ts` → `views/storefront/CatalogView.vue`
→ `components/storefront/ProductCatalog.vue` → `ProductCard.vue`.
Данные приходят через `stores/catalog.ts` → `services/catalog.ts` → `services/http.ts`.
Добавление в корзину проходит через событие компонента, `useCartActions` и cart store.

Это соглашения Shoply на основе практик Vue, а не обязательная для Vue структура.
[Рекомендации Vue по состоянию](https://vuejs.org/guide/scaling-up/state-management.html),
[маршрутизации](https://vuejs.org/guide/scaling-up/routing.html) и
[composables](https://vuejs.org/guide/reusability/composables.html).

### Навигация и сохранение состояния

Основные адреса витрины: `#/catalog`, `#/product/ID`, `#/cart`, `#/checkout`,
`#/success`. Админка: `/admin.html#/settings`, `#/products`, `#/orders`.
Старые ссылки (`#catalog`, `#product/ID`, `#cart` и разделы админки) принимаются
при открытии, переходах и навигации назад/вперёд. Они нормализуются без добавления
лишнего шага в историю. Неизвестный товар ведёт в каталог; пустая корзина не
открывает оформление; подтверждение доступно только после ответа сервера.

`KeepAlive` сохраняет каталог с фильтрами и незавершённую форму заказа при
переходах. После успешного заказа создаётся чистая форма для следующего.
В админке сохраняются черновики оформления и товара между разделами;
заказы при повторном открытии загружаются заново. Выход уничтожает черновики.
Корзина — маршрут поверх текущей страницы: `RouterView` отображает сохранённый
фоновый маршрут, а `useCartOverlay` управляет диалогом и фокусом.

### Соглашения Vue и TypeScript

- Компоненты — многословные PascalCase `.vue`-файлы; `App.vue` — исключение.
- Используются `<script setup lang="ts">`, типизированные `defineProps` и
  `defineEmits`. Props не изменяются; редактируемые данные копируются в черновик.
- Pinia использует setup stores (`defineStore` с функцией). Для извлечения
  реактивного состояния применяется `storeToRefs`; методы можно извлекать напрямую.
- Производные значения — `computed`; наблюдение и побочные эффекты — `watch`
  и хуки жизненного цикла с очисткой таймеров и обработчиков.
- Composables называются `use…` и возвращают обычный объект с refs и методами.
  Извлекайте самостоятельные обязанности, не создавайте функцию для каждого выражения.
- Импорты общих модулей используют `@/` (это `frontend/src/`); соседние файлы
  могут использовать относительные импорты. Имена описывают смысл, например `formatPrice`.
- JSDoc на русском объясняет назначение функций, контракты, ограничения и побочные эффекты.
- ESLint проверяет Vue/TypeScript, Prettier оформляет код: два пробела,
  один атрибут на строку в многострочных тегах, одинарные кавычки в скриптах.
  `npm run format` форматирует только исходники фронтенда и связанные конфигурации.
  `npm run lint` и `npm run format:check` входят в GitHub Actions.

CSS подключается через `assets/styles/storefront.css` и `admin-entry.css`:
токены → стили страницы → общие кнопки → переключатель темы. Порядок сохраняет
каскад существующего оформления. Ранняя установка темы выполняется в HTML
до загрузки CSS; собранные CSS публикуются вместе с JavaScript в `assets/build/`.
Vite видит статические файлы `public`, но не копирует весь каталог при сборке:
публикация по-прежнему переносит только HTML и новые файлы сборки.

## Ограничения и материалы

Онлайн-оплата не подключена: заказ сохраняется со статусом «Ожидает оплаты», доставка уточняется отдельно. Подготовка контейнера и GitHub Actions выполнена; подключение хостинга и HTTPS — отдельный этап. См. [деплой в Dokploy](docs/dokploy.md). GitHub Pages не запускает Python/SQLite; рабочему магазину нужен серверный хостинг.

Лицензия Inter — `public/assets/fonts/Inter-LICENSE.txt`.

Инструкции для работы с проектом: [AGENTS.md](AGENTS.md).

### Тестовые данные

В админке `/admin.html#/test-data` можно создавать от 1 до 100 товаров за один
запуск. У каждого товара случайные название, цена, категория и свойства, а также
2–3 разные фотографии из локального набора. Фотографии распределяются случайно
и могут не соответствовать названию товара. Источники и лицензия перечислены в
[docs/test-product-photos.md](docs/test-product-photos.md).

Для приложения это обычные товары. Сервер хранит происхождение в отдельном поле
`products.is_test`, которое не меняется при редактировании. Существующие товары
при обновлении схемы получают значение `0`. Обычное API создания товара не
позволяет выставлять этот признак.

«Удалить все тестовые данные» после подтверждения физически удаляет все товары
генератора, включая скрытые и отредактированные. Обычные товары, любые заказы,
пользовательские загрузки и общий набор фотографий сохраняются. Если тестовый
товар уже был в заказе, его название, цена и количество остаются в истории.
Генерация и очистка доступны только администратору, каждая операция атомарна.
